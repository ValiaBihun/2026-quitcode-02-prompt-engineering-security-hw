# Quote calculator

Крихітний TS-модуль для розрахунку кошторису проєкту автоматизації. Усі
грошові суми — цілі числа в центах (щоб уникнути похибок float).

## Встановлення і запуск

```bash
npm install
npm test         # vitest run
npm run typecheck
```

## API

### `estimateTotalCents(input: QuoteInput): number`

```ts
interface QuoteInput {
  hours: number;           // оцінка робіт у годинах
  rateCents: number;       // ставка за годину, в центах (5000 = $50.00)
  discountPercent?: number; // знижка у відсотках, 0..100
}
```

Рахує ціну проєкту в центах з урахуванням знижки.

```ts
estimateTotalCents({ hours: 10, rateCents: 5000, discountPercent: 10 }); // 45000
```

**Кидає `RangeError`**, якщо:
- `discountPercent` поза межами `0..100` (напр. `150`, `-20`) чи не скінченний (`NaN`);
- `hours` чи `rateCents` не скінченні (`NaN`/`Infinity`).

Замість того, щоб мовчки повернути `NaN`, від'ємну чи завищену суму.

### `splitInstallments(totalCents: number, parts: number): number[]`

Ділить суму на `parts` платежів. Сума елементів результату **завжди точно
дорівнює** `totalCents` — залишкові центи від округлення розподіляються по
одному на перші платежі, платежі відрізняються максимум на 1 цент.

```ts
splitInstallments(100, 3); // [34, 33, 33] — сума = 100, а не 99
```

**Кидає `RangeError`**, якщо `totalCents` не ціле число (напр. `100.5`) або
`parts` не додатне ціле число (`0`, від'ємне чи дробове) — замість того, щоб
мовчки порахувати неточну суму чи загубити її.

### `formatMoney(cents: number): string`

Форматує центи як `"$1,234.50"`. Коректно обробляє від'ємні суми (`"-$1.05"`)
і дробову частину менше 10 центів (`"$0.05"`).

## Інваріанти, підтверджені тестами (`src/quote.test.ts`)

- Усі суми — цілі числа в центах, ніякого float-дрейфу.
- `discountPercent`, `hours`, `rateCents` мають бути скінченними числами;
  `discountPercent` — ще й у межах `0..100`. Порушення — це помилка виклику
  (`RangeError`), а не тихо порахований `NaN` чи неправильний результат.
- `splitInstallments` ніколи не губить і не додає центи: сума платежів завжди
  дорівнює вхідній сумі. `totalCents` має бути цілим числом, а `parts` —
  додатним цілим числом — інакше помилка виклику, а не тиха неточна сума чи
  порожній масив.
