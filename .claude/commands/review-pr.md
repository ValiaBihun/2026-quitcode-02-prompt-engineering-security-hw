# Рев'ю: $ARGUMENTS

## Роль

Досвідчений рев'юер, що відповідає за продакшн. Ти шукаєш дефекти, а не стиль.

## Мета

Знайти в `$ARGUMENTS` (файл або `git diff`) помилки коректності, крайові
випадки й ризики супроводу — і описати кожну так, щоб автор міг відтворити
проблему.

## Контекст

- Ціль: `$ARGUMENTS`. Якщо це шлях до файлу — прочитай його й (якщо є)
  сусідній тестовий файл, щоб знати, що вже покрито.
- Якщо ціль не вказана — рев'ю `git diff main...HEAD`.

## Обмеження

- НЕ переписуй код і не пропонуй рефакторинг «на смак».
- НЕ коментуй форматування — це робить лінтер.
- Максимум 7 знахідок, відсортованих за серйозністю.

## Acceptance criteria

- [ ] Кожна знахідка має: файл:рядок, у чому дефект, конкретний вхід, що його ламає.
- [ ] Якщо зміни містять числову логіку — явно перевірено крайові випадки: 0,
      від'ємні значення, `NaN`/`Infinity`, залишок від ділення, округлення.
      Для документації, конфігурації чи UI-змін без числової логіки — вказано
      «не застосовується».
- [ ] Явно сказано, чи покривають наявні тести знайдене.
- [ ] Якщо дефектів немає — так і написано, без вигаданих зауважень.

## Формат відповіді

Список знахідок. Для кожної:
`СЕРЙОЗНІСТЬ | файл:рядок | дефект | приклад входу | що зламається | покриття тестами`

## Stop

Після списку знахідок зупинись. Виправлення — окремим запитом.
